Security Checks Performed

Our scanner runs 12+ specialized security tests across 6 core vulnerability categories to detect real threats, misconfigurations, and data exposure risks in your web application.

CORE CHECKS
6 primary vulnerability types
Cross-Site Scripting (XSS)
High Severity

Tests whether malicious JavaScript can be injected into web pages and executed in victims' browsers. Checks both URL parameters and HTML form fields for reflected XSS using real attack payloads including <script>alert()</script>, <img onerror>, <svg onload>, and template injection.

URL parameter injection Form field injection 10 XSS payloads
SQL Injection (SQLi)
High Severity

Detects if the application passes user input directly into database queries without sanitization. Uses error-based detection targeting MySQL, PostgreSQL, SQLite, MSSQL, and Oracle. Tests 12 SQLi payloads including UNION-based and boolean-based injections across all discoverable URL parameters and form fields.

Error-based detection 5 DB engines Forms & URL params
Security Misconfiguration
Medium Severity

Verifies 7 critical HTTP security headers — Content-Security-Policy, Strict-Transport-Security, X-Frame-Options, X-Content-Type-Options, X-XSS-Protection, Referrer-Policy, and Permissions-Policy. Also detects server version disclosure and checks HTTPS enforcement.

7 security headers Version disclosure HTTPS enforcement
Cross-Site Request Forgery (CSRF)
Medium Severity

Inspects every POST form for CSRF token protection. Checks 12 common token field names including csrf_token, _token, authenticity_token, csrfmiddlewaretoken, and __RequestVerificationToken. Forms without CSRF tokens allow attackers to trick logged-in users into unintended actions.

All POST forms 12 token names State-change endpoints
Directory Traversal
High Severity

Tests URL parameters that look like file references (file, path, page, include, template, etc.) with 6 traversal payloads including ../../../etc/passwd, Windows variants, and URL-encoded forms. Detects full server filesystem access via manipulated paths.

6 traversal payloads Linux & Windows paths URL-encoded variants
Sensitive File Exposure
High Severity

Probes 40+ known paths for publicly accessible files that should never be reachable — .env secrets, .git/config, database dumps (db.sql, backup.zip), phpinfo.php, wp-config.php, phpMyAdmin panels, error logs, and admin portals left unprotected on the web root.

40+ sensitive paths Config, backup & logs Admin panels & dumps
ADDITIONAL CHECKS
6 supplementary tests
Clickjacking Protection
Medium

Checks for X-Frame-Options or CSP frame-ancestors to block hidden iframe embedding used for UI redress attacks.

SSL / HTTPS Security
Medium

Verifies the site uses HTTPS encryption. Plain HTTP sites expose all transmitted data to network eavesdroppers.

Open Redirect
Medium

Tests url, redirect, next, return and 12 other redirect params for unvalidated external redirects.

Sensitive Data in Source
High

Scans page HTML source for hardcoded API keys, passwords, tokens, AWS credentials, and DB connection strings left in client-side code.

Weak Authentication
Medium

Detects login forms lacking CAPTCHA or rate-limiting (brute-force susceptible) and credentials transmitted over unencrypted HTTP.

Content Security Policy
Medium

Validates a CSP header is present and restricts which scripts, styles, and external resources browsers are allowed to load.

AI-POWERED CHECKS
Powered by DeepSeek-R1 & Qwen2.5-Coder

These AI-exclusive tests go beyond static rule-based detection. DeepSeek-R1 reasons through complex attack scenarios while Qwen2.5-Coder crafts custom exploit scripts on-the-fly — finding vulnerabilities that no signature list ever could.

Server-Side Request Forgery (SSRF)
High

AI probes URL parameters that fetch external resources, injecting internal addresses like http://169.254.169.254 to detect cloud metadata server access, internal port scanning, and service enumeration.

CORS Misconfiguration
Medium

AI sends crafted Origin: headers with attacker-controlled domains and analyzes Access-Control-Allow-Origin responses to detect overly permissive CORS policies that allow credential theft from external sites.

Insecure Direct Object Reference (IDOR)
High

AI identifies URL parameters that reference objects by sequential ID (user_id=1, order=42) and enumerates adjacent IDs to detect unauthorized cross-user data access without authentication bypasses.

Business Logic & API Discovery
High

AI discovers hidden API endpoints (/api/v1/admin, /internal), tests negative-value price manipulation, coupon stacking, and workflow bypass flaws that no signature-based scanner could ever detect.

HTTP Parameter Pollution (HPP)
Medium

AI sends duplicate parameters (?id=1&id=2) to detect inconsistent server-side parsing that can bypass WAF rules, override privilege checks, or corrupt application logic on different backend frameworks.

XML External Entity (XXE)
High

AI locates XML-accepting endpoints and injects crafted DOCTYPE payloads with external entity references to detect file disclosure (/etc/passwd), SSRF-via-XML, and out-of-band data exfiltration through XML parsers.
